两层各管一段：PAC 决定"要不要交给 xpilot"，xray 路由决定"交进来之后走节点还是直连"。任何一层判为直连，流量都不会走节点。

系统代理为 PAC 自动配置模式，地址（注册表 AutoConfigURL）：…。浏览器访问每个网址前都会先执行 PAC 脚本，对每个请求返回两种结果之一：

DIRECT浏览器直连目标网站，流量完全不经过 xpilot / xray
PROXY 127.0.0.1:10808交给本地 xray，再由下面的 xray 路由做二次分流
  • PAC 内容来自用户数据目录（%AppData%\xpilot）下的 html/pac 文件，由你自行维护（标准 FindProxyForURL 语法），xpilot 不生成它的内容，只负责通过 http://127.0.0.1:6001/pac 提供给系统；
  • 修改 html/pac 后点标题栏的"刷新 PAC"：xpilot 给 PAC 地址追加新的随机参数写回注册表并广播系统刷新，浏览器检测到 URL 变化会立即重新拉取规则；不手动刷新的话，最迟下一轮选点也会自动生效；
  • "打开注册表"按钮可直接定位到系统代理所在的注册表项（Internet Settings）。

② xray 路由（本地代理 127.0.0.1:10808，后执行）

只有被 PAC 交给 10808 端口的流量才会进入 xray，按下面的规则二次分流。规则由 xpilot 生成配置时写死，每次选点落地都会重建，改路由需要改代码（buildXrayConfig）。

入站：mixed 混合协议监听 127.0.0.1:10808（socks5 与 http 同端口，允许 UDP），开启流量嗅探（http/tls/quic）——从 TLS SNI、HTTP Host 还原真实目标域名，域名规则按嗅探结果匹配。

出站：共 3 个——proxy（当前选中的 vless 节点，第一个出站）、direct（freedom，本机直接连出）、block（blackhole 黑洞，已预置但当前没有规则引用）。

域名策略 domainStrategy = AsIs：路由只按域名规则匹配，不做本地 DNS 解析。不用 IPIfNonMatch 的原因：它需要先解析域名再匹配 IP 规则，而国内 ISP 的 DNS 会对被墙域名返回污染地址（例如谷歌的 203.208.x.x），这些假 IP 在 geoip 库里属于中国，国外站点会被"国内 IP → 直连"规则误判而打不开；AsIs 下未命中域名规则的域名把域名原样交给出站、由节点服务器负责解析，既不误判也更快。

顺序匹配条件走向说明
1目标 IP ∈ geoip:privatedirect127.0.0.1、192.168.x.x、10.x.x.x 等本机/内网地址
2目标域名 ∈ geosite:cndirect国内域名库（baidu.com、qq.com、12306.cn 等）
3目标 IP ∈ geoip:cndirect国内 IP 段，主要命中纯 IP 访问的目标
4其余全部流量proxy未命中上述规则的走第一个出站，即当前节点

规则自上而下匹配，命中即停；geoip.dat / geosite.dat 随 exe 内嵌、释放到用户数据目录的 html\ 文件夹加载。

核对走向：logs/xray-access.log 逐请求记录每个连接实际命中了哪个出站（proxy / direct），想确认某个域名怎么走，看它即可——本页"访问日志"标签页可以直接查看。
另外两点：选点阶段临时拉起的实测实例不带上述路由，全部流量直接走被测节点（测速口径一致，也省去 geoip/geosite 加载开销）；节点热替换只替换 proxy 出站，路由规则保持不变。
